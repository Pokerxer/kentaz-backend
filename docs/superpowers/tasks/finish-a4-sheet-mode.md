| **Print-dialog notice** | Shown in sheet mode: Scale 100%, Margins None. |

### Two decisions worth knowing

- **The nudge is a transform on the grid inside the page, not on the page.** The
  paper stays exactly A4 however far the labels shift, and the sheet's
  `overflow: hidden` clips a label pushed off the edge rather than spilling it
  onto the next sheet. Verified: at X +1.5 / Y −2 the `/MediaBox` is still A4.
- **The nudge is remembered.** Drift belongs to the printer, not to one job.
  Making the user rediscover it costs a sheet of forty stickers each time.

---

## Do not

- **Do not convert the barcodes to EAN-13 or UPC-A.** The SKUs are 12-digit numerics but
  only ~10% carry a valid check digit, so those symbologies would require *altering the
  number*, which breaks the POS match. This was designed and deliberately abandoned.
- **Do not run `backend/scripts/backfillVariantSkus.js`.** It is written, idempotent, and
  would fill the 103 blank SKUs — but the owner has asked that existing data stay
  untouched. It is theirs to run. **Still not run.**
- **Do not rewrite existing SKUs anywhere.** They are real codes off real products;
  changing one orphans every tag already stuck on stock.

## Watch out for

- **Stale service worker.** The admin is a PWA (`next-pwa`, `skipWaiting: true`). After
  changing client code, unregister the service worker in DevTools → Application and hard
  reload, or the old bundle keeps being served. This already caused one false bug report.
- **`admin/.next.root-owned-june20/`** — a root-owned build dir from June that broke
  `next build`; it was moved aside. Needs `sudo rm -rf` to clear. Not related to this work.
- **Forms that map variants field-by-field.** `products/[id]/edit` rebuilds each variant
  from a field list; anything not listed is silently dropped on save. `sku` must stay in
  that list.

**Two Chromium behaviours to know if you rerun this:**

1. It rounds the CSS page box to whole PostScript points, so a 50 mm page reports as
   50.12 mm and A4 as 209.89 mm. That is the renderer, not the stylesheet — the previous
   session saw the same thing and recorded it as "50.1 × 25.1 mm". **Assert with
   tolerance, not equality.**
2. `page.pdf()` fires `afterprint`, which this page listens for to unmount the print
   DOM. **Make every DOM assertion before generating the PDF**, or the tree is gone.
